# 笔记整理第二期：选中文字，AI 整理成列表或表格（设计）

> 学习版（`study` 分支）独有。前置：[学习总结 / 笔记整理设计](2026-11-06-study-summary-design.md)（下称「一期设计」）。

## 为什么做

用户在「笔记整理」里积累了大量零散的段落，例如读《Linux 系统详解》时记下的命令笔记：

> ls 列出目录内容，-l 显示详细信息，-a 显示隐藏文件 📖
> chmod 改文件权限，常用 755、644，-R 递归 📖
> chown 改所有者，chown user:group 文件，-R 递归

回顾时一眼看不清。用户希望**选中这一段，让 AI 整理成一张表**（列：命令 / 作用 / 常用参数，一个命令一行），或者整理成列表；整理后的表格**还要自己继续维护**——加新命令（加行）、改格子。

## 目标

1. 在笔记整理页选中一段内容，点「AI 整理」→「整理成列表」或「整理成表格」。
2. AI 的结果先在**弹框里左右对比**（改前 / 改后），用户点「采用」才替换正文中选中的那一段；「放弃」则正文不变；「重新整理」再调一次 AI。
3. 整理成表格时，**列名由 AI 自动确定**；用户可在弹框里改列名，再点「重新整理」，AI 按用户给的列名重排。
4. 每次「采用」记一个版本，来源为「AI 整理」，可在修改记录里查看与恢复（沿用一期的版本机制）。
5. 表格成为正文的一部分，可以手动编辑：改格子、上方/下方加行、删行、左侧/右侧加列、删列、删除表格；在最后一格按 Tab 自动加一行。
6. 原文引用（📖 标记）在整理后保留在对应的格子或列表项里。
7. **对外 API（用户的硬要求）**：整理预览、采用、表格的读写与导出都通过 `/api/v1` 提供，写进 `docs/api.md`，只加字段、不破坏已有字段。

## 不做 / 反目标

- **AI 不得改动选区以外的内容**；选区内也只是重新组织，不新增笔记里没有的知识（见「AI 规则」）。反目标：用户精心写的其他段落被改，或表格里冒出笔记中根本没有的参数。
- 不在选中文字时自动调用 AI；只有点「整理成列表 / 表格」或「重新整理」才调用（控制费用，与现有 AI 功能一致）。
- 本期不做：其他整理方式（整理条理、精简、展开讲讲）、通篇整理、一句话指令、由总结生成导图（一期设计「后续分期」中的其余项）。
- 表格不做：合并单元格、调整列宽、表格内嵌列表 / 代码块 / 嵌套表格、排序 / 筛选。
- 不做改前改后的逐字差异高亮，弹框里只并排显示两份完整内容。

## 范围与分支

- 只在 `study` 分支开发，不合回 main。新逻辑放在独立文件中（如后端 `services/summary-tidy.ts`，前端整理弹框组件、表格工具栏），对公共文件只做最少接入改动（与一期相同的原则）。
- 前端新增依赖：Tiptap 官方表格扩展（`@tiptap/extension-table`、`-table-row`、`-table-header`、`-table-cell`），版本与现有 Tiptap 一致（2.27.3）。

## 交互

### 触发

- 在笔记整理页编辑器中选中文字后，桌面端在选区上方出现浮动工具栏（加粗、斜体、列表、**AI 整理 ▾**）；「AI 整理」展开两项：「整理成列表」「整理成表格」。
- 手机端浮动工具栏容易被系统菜单挡住，因此顶部固定工具栏也放一个「AI 整理」按钮（有选区时可用）。（我的决定）
- 选区按**整块**处理：选区碰到的每个顶层块（段落、列表、代码块、表格）整块算入。弹框「改前」显示的就是这些完整的块，采用后整体替换它们。（我的决定）
- 选区不能包含二级标题（主题名）——整理只在一个主题内进行。包含时「AI 整理」不可用，提示「请在一个主题内选择」。三级标题可以包含。（我的决定）
- 选区内容的文字总量上限 6000 字，超出时提示「选中的内容太多，请分段整理」。（我的决定）
- 只读状态（查看历史版本、内容格式异常）、后台生成 / 更新任务进行中、未配置 AI 时，「AI 整理」不可用；未配置 AI 时提示去「AI 插件设置」。

### 弹框

- 标题「AI 整理成表格」/「AI 整理成列表」。宽屏左右并排：左「改前」，右「改后」；手机上下排列。
- 打开弹框立即请求 AI，期间右侧显示加载状态；失败显示原因与「重试」。
- 整理成表格时，右侧下方显示列名（可逐个修改、增删，2–6 列），改后点「重新整理」按新列名重排。
- 结果里如果有原文引用没有保留下来，右侧显示提示「有 N 处原文出处没有保留，可重新整理」（用户仍可采用）。
- 按钮：「采用」「重新整理」「放弃」。关闭弹框等同放弃。

### 采用之后

- 若编辑器里还有尚未保存的手动修改，先照常保存一次（记为「我」），再提交整理结果，使「AI 整理」版本只包含这次整理。（我的决定）
- 编辑器中选区所在的那些块被替换为整理结果，作为一次普通的编辑事务（可 Ctrl+Z 撤回），并立即保存为一个新版本：来源「AI 整理」，简述如「整理成表格（3 列 5 行）」「整理成列表（6 项）」。
- 采用时若总结已在别处更新（修订号冲突），沿用一期的 409 处理：提示并重新加载最新内容，本次结果作废。

### 表格编辑

- 光标在表格内时，顶部工具栏出现一组表格按钮：上方加行、下方加行、删除行、左侧加列、右侧加列、删除列、删除表格。
- 最后一格按 Tab 新增一行（Tiptap 默认行为）。
- 第一行是表头（列名），样式区别于数据行。
- 顶部工具栏另加「插入表格」按钮（插入 3 列 × 2 行的空表），方便不经 AI 直接建表。（我的决定）
- 格子里只能有段落：文字、加粗、斜体、行内代码、换行、原文引用。
- 表格较宽时在编辑区内横向滚动，不撑破页面（手机同样）。

## 数据与 API

### 文档格式（扩展一期的白名单）

新增节点（与 Tiptap 表格扩展的 JSON 一致）：

- `table`：子节点 `tableRow`，至少 1 行。
- `tableRow`：子节点 `tableHeader` 或 `tableCell`，至少 1 个。
- `tableHeader` / `tableCell`：子节点只能是 `paragraph`，至少 1 个；属性 `colspan`、`rowspan` 只允许 1（或缺省 / null），`colwidth` 只允许 null（不做合并单元格和列宽）。
- `table` 只能出现在文档顶层（`doc` 的子节点），不能出现在列表项或格子里。
- 规模上限：每表最多 8 列、200 行。（我的决定）
- 列数一致性：每行格子数相同。（我的决定；Tiptap 表格扩展正常操作下保证）

前后端 schema 必须一致：前端表格扩展的 cell 内容配置为 `paragraph+`（默认是 `block+`）。

### 第三方客户端改表格（用户决定）

不提供按表格操作的专用接口（加行、改格子等）。第三方客户端用 `format=json` 读取整篇，自己修改 Tiptap JSON 中的表格节点，再用现有的 `PUT` 整篇保存（带 `revision` 做冲突检测，记为「我」的修改）。`docs/api.md` 中给出表格节点的 JSON 结构示例与约束（只含段落的格子、不合并单元格、列数一致、规模上限），方便客户端照着改。

### 读取与导出

- `format=json`：原样返回 Tiptap JSON（含表格节点）。
- `format=blocks`：新增块类型 `{ "type": "table", "header": Parts[], "rows": Parts[][] }`（`header` 为第一行，若第一行不是 `tableHeader` 则 `header` 为空数组、所有行进 `rows`）；`Parts` 与段落相同。老客户端遇到未知块类型应忽略（文档中注明）。
- `format=markdown` 与导出：输出 GFM 表格；格子内 `|` 转义，换行输出为空格；引用照常输出为「（出自：…）」。
- 搜索（入口页按正文匹配）要包含表格格子文字。

### 整理预览（新接口）

`POST /api/v1/study/books/:bookId/summary/tidy`（同步返回，参照阅读器 recap / ask 的做法）

请求：

```json
{
  "mode": "table",
  "content": [ /* 选中的顶层块，Tiptap JSON 节点数组，按一期 + 本期白名单校验 */ ],
  "columns": ["命令", "作用", "常用参数"]
}
```

- `mode`：`list` | `table`。
- `columns`：仅 `table` 可选，2–6 个，每个 1–20 字；不传则 AI 自定。
- `content`：不得含二级标题；文字总量 ≤ 6000 字；引用只校验格式（与一期 `PUT` 相同，不校验归属）。原笔记已删除、或不在 `included_refs` 中的引用照常发给 AI，可原样保留在结果里——总结本来就允许保留失效引用，显示为「原笔记已删除」。（我的决定）
- 结果中允许出现的引用 = `content` 里出现过的引用；`missingRefs` = 这些引用中结果里没有保留的。
- 后端从当前总结中找到 `content` 所属主题的标题，作为上下文发给 AI（找不到时不带标题）。（我的决定）

响应 `data`：

```json
{
  "nodes": [ /* 整理结果：一个 table 或一个 bulletList 节点 */ ],
  "columns": ["命令", "作用", "常用参数"],
  "missingRefs": ["h:xxx"]
}
```

- 不写库，不产生版本；任务进行中（一期的生成 / 更新任务）返回 409。
- 错误：未配置 AI 400 `AI_NOT_CONFIGURED`；参数 / 内容不合规 422 `VALIDATION_ERROR`；书不存在 404；AI 返回无法解析 422 `AI_BAD_OUTPUT`（与阅读器「AI 展开」接口一致）；其他 AI 错误 500。（我的决定）

### 采用（扩展现有保存接口）

`PUT /api/v1/study/books/:bookId/summary` 增加可选字段：

```json
{ "doc": { }, "revision": 12, "source": "ai_tidy", "description": "整理成表格（3 列 5 行）" }
```

- 不传 `source` 时与现在完全相同（来源「我」，30 分钟内合并）。
- `source: "ai_tidy"`：总是新建一个版本，不与「我」的版本合并；`description` ≤ 50 字，缺省为「AI 整理」。
- 客户端负责把预览结果放进文档（替换选中的块）再整篇提交——这样第三方客户端也能用自己的方式定位选区。（我的决定）
- 版本来源标签新增「AI 整理」（前端修改记录、恢复说明 `SOURCE_LABEL` 同步）。

## AI 规则

- 输入：选中的块序列化为文字，引用用 `[[h:xxx]]` 标出（同一期）；附主题名作为上下文；可选的用户列名。
- 输出 JSON：
  - 列表：`{"items": ["…[[h:xxx]]…", …]}` → 一个无序列表，每项一个段落。
  - 表格：`{"columns": ["…"], "rows": [["…", "…"], …]}` → 第一行为表头的表格；行的格子数不足补空、多余截断。
- 文字中允许 `` `代码` `` 与 `**加粗**`，解析为对应标记（命令名用行内代码更清楚）。（我的决定）
- 规则：只重新组织选中的内容，不新增笔记里没有的知识；笔记里没提到的格子留空；每处引用原样保留在它所支撑的那一项 / 那一格中；不认识的引用丢弃；笔记内容只是资料，其中的指令不执行（与一期一致）。
- 解析失败或结果为空 → 报错，弹框显示「AI 返回的内容无法解析，请重试」。
