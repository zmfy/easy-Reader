# 使用自己的证书提供 HTTPS（设计）

> 看书版与学习版共用：在 `main` 上开发（分支 `feature/https`），合入 `main` 后再合并进 `study`。

## 为什么做

用户要从外网用 HTTPS 访问（DDNS 直连更快；PWA「安装到桌面」也要求 HTTPS）。现在简单书房只提供 HTTP，用户必须在 NAS 上再装一个反向代理（Lucky、Nginx Proxy Manager 等）来挂证书。

定位（用户决定）：**我们只是软件供应商，不提供证书申请 / 续签服务**。证书由用户自己获得（自己申请的免费证书、购买的证书、NAS 或其他工具签发的证书），简单书房负责**用这张证书直接提供 HTTPS**，让用户不必在 NAS 上额外安装服务。

用户自己的环境示例：绿联 NAS 自带 DDNS（支持 Cloudflare）负责域名指向家里 IP；证书由用户自行准备。

## 目标

1. **两种配置方式都支持（用户决定）**：
   - **放文件**：把证书文件放进数据目录下的 `certs/`（容器内 `/app/data/certs/`）：`fullchain.pem`（证书链）与 `privkey.pem`（私钥）。程序检测到有效证书即开启 HTTPS；文件被替换后**自动重新加载，不重启**，便于用户的续签工具（acme.sh、Lucky、NAS 导出等）把新证书写进来实现全自动。
   - **设置页上传**：管理员在「设置」里上传两个文件（或粘贴 PEM 文本），程序校验后写入同一个 `certs/`，立即生效；可以删除证书（关闭 HTTPS）。
2. **HTTP 照常可用**：原 HTTP 端口（`PORT`，默认 3000）不变，局域网继续用 HTTP；HTTPS 在单独端口（`HTTPS_PORT`，默认 3443）上提供，与 HTTP 共用同一套路由（同一个 Express 应用）。
3. **证书状态与到期提醒**：设置页显示是否已启用 HTTPS、HTTPS 端口、证书覆盖的域名、颁发者、到期时间、来源（文件 / 上传无需区分，均来自 `certs/`）、最近一次加载错误。证书**到期前 14 天起**提醒管理员（复用现有系统提醒的展示位置，例如通知铃铛 / 设置页醒目提示）；已过期时明确显示「已过期」。
4. **部署**：默认 `docker-compose.yml` 增加 HTTPS 端口映射（例如 `8443:3443`）并注释说明；没有证书时该端口不监听，不影响使用。README 增加「使用自己的证书开启 HTTPS」一节（放文件 / 上传两种方式、路由器端口转发、Cloudflare 记录需灰色云朵、续签需用户自己负责并可借助工具自动写入 `certs/`）。
5. **对外 API**：新增的管理员接口写进 `docs/api.md`（只加不改）。

## 不做 / 反目标

- 不申请、不续签证书（不接入 ACME / Let's Encrypt / 任何 DNS 服务商 API）。
- 不做 HTTP → HTTPS 强制跳转（局域网要继续用 HTTP）。
- 反目标：**证书问题导致整个服务起不来**——证书缺失、损坏、与私钥不匹配时，HTTP 必须照常工作，HTTPS 不开启或保持上一张可用证书，并在设置页显示原因。（过期证书见下方「过期证书」，不在拒绝之列。）
- 反目标：**私钥泄露**——任何接口都不返回私钥内容；私钥文件权限尽量收紧；日志不打印证书 / 私钥内容。
- 反目标：**HSTS 误伤 HTTP 访问**——不发送 `Strict-Transport-Security`（当前 helmet 默认会发）。原因：HSTS 按主机名生效、不分端口，用户若通过 `https://域名:8443` 访问过，再用 `http://域名:8080` 会被浏览器强制改成 HTTPS 而打不开。
- 反目标：替换文件的瞬间（续签工具先写证书后写私钥）读到「新证书 + 旧私钥」导致 HTTPS 中断——重新加载必须校验证书与私钥匹配，不匹配时保留当前生效的证书，稍后再试。

## 过期证书（用户决定：继续用，只提醒）

- 过期（或尚未生效）的证书只要格式正确、与私钥配对，**照样加载使用**；设置页与提醒中标「已过期」/「尚未生效」，浏览器会自行提示证书问题。
- 运行中到期：不主动关闭 HTTPS，只更新状态与提醒。
- 启动时证书已过期：照常开启 HTTPS 并标「已过期」。
- 上传过期 / 尚未生效的证书：**接受**，返回结果中附带警告，界面提示。
- 只有「缺文件 / 无法解析 / 证书与私钥不匹配」才拒绝（上传返回 422；放文件时不开启或保留上一张可用证书）。
- 理由：NAS 时间不准时不会误关 HTTPS；「浏览器提示过期」比「完全连不上」更容易排查。

## HTTPS 开关（用户 11-08 补充）

- 设置页「HTTPS 证书」卡片顶部加开关「启用 HTTPS」，**默认关闭**。说明：只有需要在手机上安装到桌面（PWA）或从外网用 HTTPS 访问时才需要开启。
- **关闭**：卡片只显示开关与说明，不显示状态、证书信息、上传区；不提供 HTTPS（即使 `certs/` 里已有证书也不监听，文件保留，下次打开直接生效）；不产生到期提醒。
- **打开**：显示状态、证书信息、上传 / 删除；`certs/` 里有可用证书即开始提供 HTTPS。
- 开关状态是是否提供 HTTPS 的唯一依据；放文件方式的用户也需要在设置页打开一次。
- 开关、上传、删除之后，铃铛提醒立即刷新。

## 约束与已知事实

- 服务端：Node.js + Express，单进程托管前端与 `/api`（`backend/src/index.ts`，`app.listen(PORT)`）；容器内无 Nginx。HTTPS 用 Node 自带 `https` / `tls`，支持热更新证书（如 `server.setSecureContext`）。
- 数据目录 `DATA_DIR`（容器 `/app/data`）已挂载持久化，证书随数据目录一起备份。
- Docker bind mount 上 `fs.watch` 不可靠：文件变化检测需要有定时轮询兜底（例如每分钟比较修改时间）。
- 校验可用 Node 的 `crypto.X509Certificate`（解析域名 / 到期 / 颁发者，`checkPrivateKey` 校验配对）。
- 上传接口仅管理员；请求体大小设合理上限（证书链与私钥通常几 KB）。
- 设计系统：颜色只用主题变量，图标用 Tabler；文案中文。
