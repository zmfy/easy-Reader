# 学习总结：把一本书里学到的「点」整理成「面」（设计）

> 取代同日的「笔记列表（跨书卡片）」设计：用户不要一张张卡片自己去串，要的是按主题组织的归纳总结。

## 为什么做

学习版的划线、批注、导图知识点都是零散的「点」。用户读完一本书（例：《Linux 系统详解》，读时记了很多命令），希望最后得到一份**这本书的学习笔记**：按主题组织（「文件与权限」「进程管理」「网络命令」……），把点串成面。
这份总结用来**回顾时阅读**；理解加深后**自己改写**；读得更多、记了新笔记后能**更新**，但**不能冲掉自己改过的内容**；每次修改都**留有记录**，能查到修改的时间点（用户原话）。

## 目标

1. 每本书一份学习总结：按主题分节的文章，AI 根据该书的划线、批注、知识点生成初版（用户点击才调用）。
2. 所见即所得编辑（像 Word：工具栏加粗、标题、列表等），自动保存。
3. 「更新」：只把**上次整理之后新增的笔记**补充进合适的主题（或新建主题），**不改动已有内容**。
4. 修改记录：每个版本记录时间、来源（我 / AI 生成 / AI 补充 / 恢复）、简述；可查看任一历史版本的内容，并可**恢复**到该版本（恢复本身产生一个新版本，不删除任何历史）。
5. 总结里提到的点可以点回原文（📖）：打开阅读器跳到出处。
6. 入口页「学习总结」：列出所有书的总结，可搜索；有笔记但还没总结的书显示「生成总结」。
7. **对外 API（用户决定，必须遵守）**：学习总结的全部能力都通过 `/api/v1` 对外提供，用户可以用自己的 App、微信小程序等调用自己的学习笔记。网页只是其中一个客户端。

## 不做 / 反目标

- **AI 不得改写已有内容**：「更新」只能追加。反目标：用户精心改过的段落被 AI 重写或删掉。
- 不在打开页面、划线、保存时自动调用 AI；只有点「生成总结」「更新」才调用（与现有 AI 功能一致，控制费用）。
- 不做跨书合并总结、多人协作、公开分享。
- 不做修改内容的逐字差异对比（v1 只显示整版内容）。
- 本期不做 AI 改写/润色/通篇整理、由总结生成导图、问笔记、出题复习、跨书关联——这些是学习版后续分期（见文末「后续分期」）。

## 范围：学习版独有（用户决定的分支策略）

本功能只在长期分支 `study`（学习版）上开发，**不合并回 main**。main 定期单向合并进 study。`study` 由当前的 `feat/study-notes-phase1` 改名而来（它已包含学习笔记第一至三期，main 不含），本设计文档也只在 `study` 上。因此：

- 学习总结的代码放在独立文件中（新路由文件、新服务文件、新页面、新组件、新 API 模块），对公共文件（`index.ts` 路由注册、`db.ts` 建表入口、`router/index.ts`、侧栏 `DefaultLayout.vue`、`Reader.vue`、`docs/api.md`）只做最少的接入改动，便于以后合并 main 时少冲突。
- 发版：学习版镜像用同一个 Docker Hub 仓库加 `-study` 后缀，不得覆盖 `latest`（发布流程的改动不在本设计内，另行处理）。

## 对外 API 原则（用户决定）

- 网页与第三方客户端用同一套接口（`/api/v1`，JWT 登录，`docs/api.md`），只加字段、不破坏已有字段。
- **业务逻辑全部在后端**：生成、更新、保存（并发保护）、版本查看与恢复、引用解析、Markdown 导出都有接口；前端不做客户端独有的业务处理。
- 读取总结支持 `format`：`json`（默认，编辑器文档）、`blocks`（扁平块列表，便于小程序渲染，风格同章节接口的 blocks）、`markdown`。
- 写入只接受文档列明的节点与标记（白名单），其余拒绝（422）。
- 后台任务对客户端的用法：提交任务 → 轮询当前任务 → 完成后读取总结；文档写明流程与状态值。

## 页面与交互（用户已在草图中确认结构）

### 入口页：学习总结（`/notes`）

- 侧栏新增「学习总结」，位于「书架」之后（我的决定）。
- 顶部搜索：匹配书名与总结正文（子串，不区分大小写）；排序：最近更新（默认）/ 书名。
- 每本书一张卡片：书名、主题数、包含的笔记数、最后更新时间与来源（「11-06 更新（我修改）」）、主题名标签（最多显示若干个）。
  - 有未整理的新笔记：显示「有 N 条新笔记未整理」与「更新」按钮。
  - 有笔记但没有总结：显示「还没有总结 · N 条笔记」与「生成总结」按钮。
  - 没有任何笔记、也没有总结的书不出现。
- 书已被删除但总结还在：仍显示（标「书已不存在」），可打开、阅读、编辑、删除总结，不能更新、不能去原文。

### 单本总结页（`/book/:bookId/summary`）

- 顶栏：返回、标题「<书名> · 学习总结」、「修改记录」、「导出」（Markdown，我的决定）、「更新（N 条新笔记）」（无新笔记时禁用并提示「没有新笔记」）。
- 正文：所见即所得编辑器；主题为二级标题，主题内为段落/列表/代码；工具栏：加粗、斜体、二级/三级标题、无序/有序列表、行内代码、代码块、撤销/重做；显示保存状态（「已保存 10:42」/「保存中…」/「保存失败，重试」）。
- 📖 原文引用：总结中的引用是一个不可编辑的小标记（📖），悬停/长按显示所引笔记的原文摘要，点击打开阅读器。用户可以删除引用标记，但不能手写伪造引用。
- 修改记录：宽屏右侧面板，手机用底部抽屉。列表项：时间、来源标签（我 / AI 生成 / AI 补充）、简述（AI 版本由系统生成，如「新增 3 条到『进程管理』」；用户版本为「手动修改」）。点击「查看此版本」只读查看当时内容；查看时可「恢复此版本」（确认后用该版本内容覆盖当前总结，记为一个「恢复」版本；任务进行中不可恢复）。
- 首次进入且无总结：空状态 +「生成总结」按钮（显示将使用的笔记数）。AI 生成/更新过程中显示进度（如「正在整理 2/4 批」），期间编辑器只读，完成后刷新内容；失败显示原因与「重试」。
- 手机（`max-width: 768px`）：编辑器全宽，工具栏可横向滚动，修改记录用底部抽屉。

### 阅读器 / 书籍详情 / 学习导图的入口（我的决定）

- 书籍详情页、学习导图页工具栏加「学习总结」按钮 → `/book/:bookId/summary`。阅读器暂不加（避免再改 `Reader.vue`）。

## 数据与生成规则

### 输入：一本书的笔记

- 划线：原文 + 批注。
- 知识点：`mind_nodes` 中 `kind` 为 concept / event / person / custom 的节点：名称、摘要、节点批注、所在章节、上下游关系（父节点名称）。`kind = 'highlight'` 的根节点不单独作为输入（即其划线）。
- 每条笔记以稳定引用标识：`h:<highlight id>` 或 `n:<mind node id>`。

### 生成（初版）

- AI 输入：书名、按章节顺序排列的全部笔记（含引用标识）。输出：若干主题，每个主题含标题与若干段落/列表项，段落中用引用标识标注依据的笔记。
- 系统校验 AI 输出：只接受存在于输入中的引用标识，其余丢弃；无法解析时报错（不写入）。
- 记录「已整理的笔记」集合 = 本次输入的全部引用标识（包括 AI 没有引用到的）。

### 更新（追加）

- 新笔记 = 当前笔记中**不在「已整理的笔记」集合里**的那些。没有新笔记时不可更新。
- AI 输入：现有主题标题列表（取当前文档里的二级标题，用户改过的标题也照样用）+ 新笔记。输出：每条补充指定放入哪个已有主题，或新建主题。
- 系统把补充内容**追加到对应主题末尾**（新主题追加到文末），不修改、不移动已有内容；之后把新笔记并入「已整理的笔记」集合，生成一个「AI 补充」版本。
- 已整理过、后来又被修改的笔记不会再次补充（不算新笔记）；已整理过、后来被删除的笔记，其引用标记点击时提示「原笔记已删除」。

### 去原文（沿用学习导图页规则）

- 划线 → `/reader/:bookId?highlight=<id>`。
- 知识点有出处 → `/reader/:bookId?chapter=<i>&find=<名称>`，出处在阅读边界之后先确认（文案同导图页）；无出处 → `?chapter=<chapter_index>`。
- 阅读器以查看模式打开，不改阅读进度（现有行为）。

### 后台执行（用户决定）

- 「生成总结」「更新」提交后由服务器在后台执行，接口立即返回；前端轮询任务状态显示进度。
- 用户刷新、离开页面、在别处打开同一本书的总结页，都能看到进行中的任务和进度；任务完成后入口页与总结页显示新内容。
- 同一用户同一本书同一时间只能有一个生成/更新任务；重复点击返回当前任务。
- 任务失败（AI 未配置、AI 报错、输出无法解析）：不写入任何内容、不产生版本、「已整理的笔记」集合不变，记录失败原因供页面显示。
- 服务重启时进行中的任务视为失败（可重试），不得留下半写入的总结。
- 任务进行中总结只读；任务写入时与用户编辑的冲突见下方「并发保护」。

### 保存与版本

- 自动保存当前内容（防抖）。
- 版本：AI 生成、AI 补充各产生一个版本；用户编辑**按「一次编辑会话」合并为一个版本**（例如停止编辑一段时间或离开页面时落一个版本），避免每次自动保存都产生一条记录。合并的具体规则留给实现，约束：修改记录应能看出「哪天改过」，且不会因为一次编辑出现几十条记录。
- **并发保护**：总结带修订号；保存时带上读到的修订号，服务端发现已被更新（AI 补充、另一标签页的保存）时拒绝本次保存并返回最新内容，前端提示「总结已在别处更新，已载入最新内容」——不得用旧内容覆盖 AI 刚追加的内容。
- 删除总结：入口卡片或总结页提供「删除总结」（确认后删除总结与全部版本，不影响笔记本身）。删除后可重新生成。

## 约束

- 后端：Express + better-sqlite3 + zod；响应 `{ success, code, data }`；`authMiddleware`；只访问本人数据；新表在 study 分支独立的服务文件中建表（沿用 `HIGHLIGHTS_DDL` 的接入方式）。API 挂 `/api` 与 `/api/v1`，补 `docs/api.md`。
- AI：复用 `aiManager.chat`（DeepSeek / MiniMax / Ollama 均可）；未配置 AI 时按钮可点但提示「请先在设置中配置 AI」（同现有 `AI_NOT_CONFIGURED` 处理）。
- 笔记很多时（数百条）不能一次塞爆模型上下文：需要分批或限量策略，且「已整理的笔记」集合只记录真正送进 AI 的笔记（没送进去的仍算新笔记，下次更新处理）。
- 编辑器：Tiptap（Vue 3，我的决定），新依赖用精确版本号；文档以 Tiptap JSON 存储（便于系统追加内容与识别引用标记，我的决定）；Markdown 导出在后端完成，引用转为「（出自：书名 第 N 章）」形式。
- 前端：Vue 3 + Element Plus；API 走 `frontend/src/api/`；颜色取主题变量（`var(--accent)` 等）；UI 中文；确认框按钮中文。
- 测试：后端 Jest（服务与路由）、前端 Vitest（纯函数：AI 输出解析与校验、追加合并、引用提取、Markdown 导出、新笔记计算等测试先行）。

## 留给实现

- 表结构细节（总结表、版本表、「已整理的笔记」集合的存法）。
- AI 提示词、输出格式（JSON 结构）、分批策略的具体做法。
- 编辑会话合并为版本的具体时长与触发点。
- 入口页是否分页（书的数量通常不多）。
- 引用标记悬停时的原文摘要是否需要额外接口。

## 后续分期（用户确认的方向，本期不做）

学习版的一大特点是灵活使用 AI、减少用户操作。原则：**AI 只提建议，用户确认后才生效**——AI 改动先显示改前/改后对比，「采用」才写入，每次采用记一个版本（来源「AI 整理」），可随时恢复。

- 第二期：选中文字 AI 整理（整理条理 / 改成列表 / 精简 / 展开讲讲 / 改成表格）；通篇整理（按主题逐块对比、逐块采用）；一句话指令；由总结生成思维导图。
- 之后：问我的笔记（只根据本人总结与笔记回答并附出处）；出题复习（遗忘曲线）；跨书关联。
- 以上能力同样要通过 `/api/v1` 对外提供。
