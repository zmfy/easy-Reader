# PWA 第一期：装到桌面、全屏打开、继续上次的书（设计）

> 看书版与学习版共用：在 `main` 上开发（分支 `feature/pwa`），合入 `main` 后再合并进 `study`，随下一个版本的镜像发布。

## 为什么做

用户用手机读 NAS 上的书，现在每次都要打开浏览器、输地址或找书签，页面还带地址栏，不像 App。目标：像 App 一样，**手机桌面点一下图标就全屏进入，直接回到上次读的那本书**。

背景：用户目前用 Cloudflare 隧道从外网访问（较慢），准备换成 DDNS + NAS 上的 Let's Encrypt 证书（`https://域名:端口`）。PWA 安装要求 HTTPS（或 localhost），带端口的 HTTPS 也可以。

## 分期

- **第一期（本文）**：可安装、全屏、启动进入上次读的书、安装入口、新版本提示、没网提示、应用图标。
- **第二期（以后单独设计）**：离线阅读（缓存读过的章节，或整本下载）。本期不缓存书籍内容。

## 目标

1. **可安装**：提供 Web App Manifest 与 Service Worker，满足 Chrome / Edge / Safari 的安装条件。从桌面图标打开时全屏（`display: standalone`，无地址栏）。
2. **名称跟随网站名称（用户决定）**：应用名称取管理员在设置里配置的网站名称（`settings.site_name`），未设置时为「简单书房」。清单由后端动态生成。已知限制写进说明：iPhone 在「添加到主屏幕」时固定名称，之后改名需要重新添加；安卓 Chrome 会在之后某次自动更新。
3. **启动进入上次读的书（用户决定）**：从桌面图标打开时，进入该用户**最近有阅读进度、且书仍存在**的那本书的阅读器；没有这样的书 → 书架。未登录 / 登录过期 → 先登录，登录后再进入那本书。
4. **「安装到桌面」入口**：放在右上角用户菜单中，文案「安装到桌面」。（我的决定，用户认可）
   - 浏览器支持安装提示（Chrome / Edge，安卓与桌面）：点击即弹出系统安装确认。
   - iPhone / iPad Safari（无安装提示）：点击显示图文步骤「点底部的分享按钮 → 选择『添加到主屏幕』」。
   - 非 HTTPS 访问（`http://` 且非 localhost）：点击提示「需要通过 HTTPS 访问才能安装到桌面」，附官网教程链接（链接先指向官网首页或文档页，教程上线后替换）。
   - 已从桌面图标打开（standalone）时不显示该入口。
5. **新版本提示**：服务器升级后，页面底部提示「有新版本，点击刷新」；点击后加载新版本。不自动刷新（避免打断阅读）。
6. **没网提示（用户决定）**：离线打开或使用中断网时，显示「没有网络连接」与「重试」按钮；不提供离线阅读。
7. **应用图标（用户决定：由我设计）**：一本打开的书 + 靛青主色（`#4338ca`，默认主题主色），提供 SVG 源文件与所需尺寸（含 192 / 512、maskable、Apple touch icon），同时补上目前缺失的 `favicon.svg`（`index.html` 已引用但文件不存在）。

## 不做 / 反目标

- 不缓存书籍内容、封面、API 数据（第二期再说）；Service Worker 只缓存前端静态资源（应用外壳）。
- 不做推送通知、后台同步。
- 反目标：**旧版本卡住**——部署新版本后用户一直看到旧页面、或新旧资源混用导致白屏。更新必须可靠（新版本提示可见、点击后确实是新版本）。
- 反目标：Service Worker 拦截 / 缓存 `/api`、`/covers`、书籍文件等请求，导致数据过期或登录异常。
- 反目标：破坏现有浏览器使用（HTTP 访问照常可用；HTTPS 浏览器用户只是多了下面「新版本 / 没网」两个提示，其余不变）。

## 约束与已知事实

- 部署形态：单容器，Express 托管前端构建产物（`backend/src/index.ts` 的 `express.static(public)` + SPA 兜底），`/api` 同源。不是 Nginx（`CLAUDE.md` 的 Nginx 描述已过时）。
- 动态清单由后端提供（例如 `GET /manifest.webmanifest`，在静态文件之前注册），无需登录；`scope` 为 `/`，`start_url` 指向一个前端「继续阅读」路由（见下）。清单内容只用公开设置（网站名称），不泄露其他信息。
- 「上次读的书」：后端 `reading_progress` 表有 `updated_at`；取当前用户 `updated_at` 最新、且 `books` 中仍存在的记录。需要一个接口给前端（例如 `GET /api/v1/reader/last-read` → `{ bookId } | null`），写进 `docs/api.md`（只加不改）。
- 前端：Vue 3 + Vite；建议 `vite-plugin-pwa`（Workbox）生成 Service Worker，`registerType: 'prompt'` 实现「有新版本，点击刷新」。依赖版本选择两周以上的稳定版，锁文件为 `frontend/package-lock.json`（npm）。
- Service Worker 与 `index.html` 必须不被长期缓存（Express 静态默认 `max-age=0` + ETag，需确认 `sw.js`、清单不被加长缓存）。
- 设计系统：颜色只用主题变量，图标用 Tabler（应用图标本身除外）。
- 学习版合并：本功能不碰学习版独有文件，合并进 `study` 时应无冲突；学习版镜像（easy-learner）同样生效。

## 审查后补充的决定

- **作用范围（用户决定）**：Service Worker、「有新版本，点击刷新」、「没有网络连接」对**所有 HTTPS 访问者**生效，不只限于从桌面图标打开。HTTP 访问下浏览器本就不允许注册 Service Worker，不受影响。
- **读完的书（我的决定）**：「上次读的书」直接取最近更新的阅读进度，不判断是否已读完——`last-read` 接口只需一条查询。
- **登录回跳（我的决定）**：现在登录后固定进 `/library`；为实现「先登录再进那本书」，登录页要支持回跳到原目标（路由守卫带上 `redirect`，只允许站内路径）。
- **合并冲突（我的决定）**：study 分支在用户菜单相同位置加了「源码」项，「安装到桌面」放在不与之相邻的位置，减少合并冲突。
- 已查明：书架路由 `/shelf`；官网 `https://easyreader.ucool.uk`（非 HTTPS 提示里的教程链接先指向官网）；学习版默认站名同样是「简单书房」。
