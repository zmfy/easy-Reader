# 笔记列表：跨书查找划线、批注与知识点（设计）

## 为什么做

学习笔记（划线、批注、导图知识点）目前只能按书查看：进阅读器看划线，进学习导图看知识点。
用户的真实场景是**跨好几本书找某条记过的内容**，主要是知识点；找的时候记得的线索不固定——可能是知识点名称里的词、自己批注里写过的话、它属于哪本书、大概什么时候记的（用户原话：「都有」）。
所以需要一个汇总所有书的笔记列表页：能搜、能筛，找到后能查看、修改、删除，并能一键打开出处所在的阅读器。

## 目标

1. 新页面「笔记」：列出当前用户所有书的**划线**与**知识点**，默认按时间倒序（最近记的在前）。
2. 一个搜索框，同时搜：知识点名称、摘要、批注、划线原文；结果中高亮命中的词。
3. 筛选：按书、按类型（划线 / 概念 / 事件 / 人物 / 自定义）、按时间（最近一周 / 最近一个月 / 自定义起止日期，用户决定）、只看有批注的。
4. 点一条在右侧面板查看完整内容，并可编辑、删除（规则见下）。
5. 「📖 去原文」打开阅读器跳到出处，行为与学习导图页一致（查看模式、后文确认）。

## 不做 / 反目标

- 不新增数据：只汇总已有的 `highlights` 与 `mind_nodes`，不改表结构（反目标：为了列表另存一份冗余笔记，和原数据不同步）。
- 列表加载**不解析书文件**：不能为了显示章节标题或判断「后文」而在打开列表时逐本解析几十本书（反目标：打开笔记页要等十几秒）。
- 不做全文检索引擎、分词、拼音搜索；子串匹配（不区分大小写）即可。
- 不在列表里新建划线或知识点（新建仍在阅读器 / 学习导图里做）。
- 不做导出、批量操作、标签（本期）。

## 列表内容（用户决定）

两种条目：

- **划线**：每条划线一张卡片（**所有**划线，不论有无批注、有无 AI 展开）。标题为划线原文开头，显示其批注。
- **知识点**：`mind_nodes` 中 `kind` 为 `concept` / `event` / `person` / `custom` 的节点。

**去重（我的决定）**：`kind = 'highlight'` 的划线根节点不单独出现——它和对应划线是同一件事，只显示划线卡片。
划线根节点上的节点批注已统一为不使用（见 fd401b5），因此不会丢信息。

## 页面与交互（用户在草图中选定 A：卡片列表 + 右侧详情）

- **入口**：侧栏导航新增「笔记」，位于「书架」之后（位置是我的决定）。路由 `/notes`，需登录。
- **顶部**：搜索框；筛选「全部书 ▾」（下拉列出有笔记的书；书已删除的笔记归入「已删除的书」一项）、类型、时间（全部 / 最近一周 / 最近一个月 / 自定义起止日期）、「只看有批注」开关、排序（最近 / 最早）。
- **列表**：卡片平铺。每张卡片：标题（划线原文开头 / 知识点名称）+ 类型标签 + 「书名 · 章节」+ 一行摘要或批注；搜索命中词高亮。
- **详情面板**（宽屏右侧固定，手机 `max-width: 768px` 用底部抽屉，沿用学习导图页的做法）：
  - 划线：完整原文、批注（可编辑）、「📖 去原文」、「删除」。不能改名（名称就是原文）。
  - 知识点：名称（「改名」）、类型、摘要、批注（可编辑）、来自哪条划线（如有）、「📖 去原文」（有出处时）、「在导图中查看」、「删除」。
- 类型颜色、标签文案与学习导图一致；主题色取 `var(--accent)`，不写死颜色。

## 搜索、筛选与时间（我的决定，除注明外）

- 搜索为子串匹配（不区分大小写），**每条只按自身字段匹配**：划线匹配原文与批注；知识点匹配名称、摘要、节点批注。划线批注命中时只出现划线卡片，不连带它下面的知识点（知识点详情里可看到「来自哪条划线」）。
- 时间一律用 `created_at`：排序、时间筛选都按创建时间（划线的 `updated_at` 不参与）。「最近一周 / 一个月」以当前时间往前推 7 / 30 天；自定义起止日期按本地日期整天计（含首尾两天）。
- 「只看有批注」：划线看划线批注，知识点看节点自身批注。
- 类型筛选为单选（全部 / 划线 / 概念 / 事件 / 人物 / 自定义）。

## 编辑与删除规则（沿用现有接口规则）

- 划线：只能改批注（`PATCH /reader/:bookId/highlights/:id`）。删除时提示与阅读器相同：「删除后批注和导图节点也会一起删除，确定删除这条划线吗？」，按钮「删除划线」。
- 知识点：改名 1–60 字、批注 ≤ 2000 字（`PATCH /reader/:bookId/mind-nodes/:id`）。删除：有子节点时确认「将同时删除它下面的 N 个节点，确定删除吗？」，按钮「删除节点」；无子节点直接删除。
- 确认框按钮全部中文（`cancelButtonText: '取消'`）。

## 去原文（沿用学习导图页）

- 划线 → `/reader/:bookId?highlight=<id>`：跳到划线并高亮。
- 知识点有出处（`source_chapter` 不为空）→ `/reader/:bookId?chapter=<i>&find=<label>`；出处在用户阅读边界之后时先确认（文案同导图页「这是你还没读到的后文，可能会剧透。确定查看吗？」）。
- 没有出处的知识点（手动节点等）→ 不显示「去原文」，改为「去阅读这一章」（`?chapter=<chapter_index>`）。
- 阅读器以查看模式打开，不改阅读进度（现有行为）。
- 「在导图中查看」→ `/book/:bookId/map`（本期不要求在导图里自动选中该节点，见「留给实现」）。

## 约束

- 后端：Express + better-sqlite3 + zod，响应 `{ success, code, data }`，`authMiddleware`；只返回当前用户的数据。
- 现有按书的接口保留不变；新增的跨书接口挂在 `/api` 与 `/api/v1` 下（与现有路由同一 Router），补 `docs/api.md`。
- 书已被删除、书文件不存在的笔记：仍出现在列表中（标「书已不存在」），可删除，不可去原文（不报错、不丢数据）。
- 性能：几十本书、上千条笔记时，列表首屏应在 1 秒内出来；搜索与筛选可在后端完成并分页，或一次取回在前端过滤——由实现决定，但不得在列表加载时解析书文件。
- 前端：Vue 3 + Element Plus，API 调用走 `frontend/src/api/`，UI 中文，图标用 Tabler / Element Plus 图标（不新增 emoji，沿用已有的 📖 文案）。
- 测试：后端 Jest、前端 Vitest；纯函数（合并去重、搜索匹配与高亮切分等）测试先行。

## 留给实现

- **章节标题**：表里只存章节序号。卡片上显示「第 N 章」还是章节标题、何时取标题（例如只在详情面板按需取一本书的目录），由实现决定，但须满足上面的性能约束。
- **「后文」判断**：现有 `listMindNodesWithLater` 需读章节文本，不适合列表批量计算。可在点击「去原文」时再按书查询（如 `GET /reader/:bookId/mind-nodes?highlightId=`）后决定是否弹确认。
- 分页方式（后端分页 / 前端虚拟滚动 / 一次性加载）。
- 「在导图中查看」是否带参数让导图页自动选中该节点（可选增强）。
- 搜索输入防抖时长、空状态文案。
