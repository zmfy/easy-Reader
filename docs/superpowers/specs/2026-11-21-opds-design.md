# OPDS 书目源（设计）

## 为什么做

用户想在**手机、iPad、墨水屏**上用第三方阅读 App（KOReader、KyBook 3、Yomu、静读天下、Readest 等）直接连 easyReader：在 App 里浏览书库、搜索、把书下载到设备上读。好处：

- 离线读、用 App 自己的排版与系统能力（墨水屏上远比浏览器流畅）
- 让 easyReader 成为家里所有阅读设备的「书源」，提高粘性

OPDS 是这类 App 通用的书目源协议。

## 目标

1. 提供 OPDS 1.2 书目源，主流客户端（KOReader、KyBook 3、静读天下等）能添加、浏览、搜索、下载。
2. **整个书库都可用**，不只 EPUB：TXT / UMD 在下载时转成带目录、UTF-8 的 EPUB（用户选的方案 B）。
3. 每个用户（含普通用户）可以自助开通，使用**专用的 OPDS 密码**，可随时重置 / 关闭。

## 不做 / 反目标

- **不做 KOReader 进度同步（KOSync）**：以后单独做第二期（用户已同意分期）。
- 不做 OPDS 2.0（JSON）：客户端支持不全，KOReader 只认 1.2。
- 不做 OPDS-PSE（漫画流式翻页）。
- 不做下载统计、按用户限制下载哪些书。
- **反目标**：
  - 用登录密码做 OPDS 认证（客户端会把密码明文存在设备上）。
  - 客户端下载到打不开 / 乱码的文件（损坏书、只在读取时修正过的 EPUB、GBK 的 TXT）。
  - 绕过 easyReader 现有的权限：用户被删除、改角色后 OPDS 也立即失效。
  - 暴露服务器上的文件路径。

## 约束

- 适用版本：**看书版（main）**，随常规流程单向合并进学习版（study）。代码放独立文件（`routes/opds.ts`、`services/opds-*.ts`），公共文件只做接入改动。
- 后端 Express + better-sqlite3，Node；不引入大型新依赖。打 zip 可用 `adm-zip`（依赖树里已有、`overrides` 已锁版本，需要改为直接依赖）。
- 现有认证只有 `Authorization: Bearer` JWT；OPDS 客户端几乎只支持 HTTP Basic，需要另做一套。
- 书库「可见的书」与网页版一致：`status` 为 `normal` / `encoding_fixed` 的书（即书库列表默认条件），`damaged` / `duplicate` / `garbled` 不出现。
- 部署常在反向代理后、端口不固定：feed 里的链接一律用**以 `/` 开头的绝对路径**（不带主机名），由客户端按 feed 地址补全。
- 更新日志按 CHANGELOG 约定写；对外说明写进 README「使用指南」和 `docs/api.md`（OPDS 单独一节，说明它不走 JWT）。

## 方案（已选 B）

| 方案 | 内容 | 取舍 |
|---|---|---|
| A. 只给原文件 | EPUB / PDF / TXT 原样下载，UMD 不列 | 最省事；但中文书库 TXT 多为 GBK、无目录，iPad / 墨水屏上乱码或无法跳章；UMD 用不了 |
| **B. TXT / UMD 转 EPUB（选中）** | 用现有解析插件的章节切分现场生成 EPUB 并缓存；读取时修正过的 EPUB 给修正版 | 三类设备、整个书库都能用；多一个 EPUB 生成模块与缓存失效逻辑 |
| C. B + KOSync 进度同步 | 墨水屏与网页互相接着读 | 只对 KOReader 有用，进度模型映射难；放到第二期 |

用户选择 B。

## 设计

### 1. 地址与认证

- 入口：`/opds`（根目录，不在 `/api` 下，便于用户记忆和填写）。所有 OPDS 地址都在 `/opds/` 下。
- **HTTP Basic**：用户名 = easyReader 用户名，密码 = 该用户的 **OPDS 专用密码**。未认证或失败返回 `401` 并带 `WWW-Authenticate: Basic realm="easyReader"`（客户端靠它弹出登录框）。
- OPDS 密码：
  - 存哈希（bcrypt，与登录密码同样做法），**不存明文**；生成时只显示一次。
  - 由系统随机生成（如 16 位字母数字，便于在墨水屏上手输时避开易混字符），用户不能自定义（我的决定：避免用户把登录密码设成 OPDS 密码）。
  - 操作：开通（生成）、重置（旧的立即失效）、关闭（删除）。
  - 新用户默认**没有** OPDS 密码，需要自己开通。
- **OPDS 密码何时作废（用户决定）**：

  | 事件 | OPDS 密码 |
  |---|---|
  | 用户自己重置 OPDS 密码 | 旧的立即作废 |
  | 用户自己 / 管理员关闭 OPDS | 作废 |
  | 管理员重置该用户的登录密码（`routes/settings.ts` 重置密码处） | **作废**（视为账号泄露处理） |
  | 删除用户 | 删除（接入 `deleteUserData`） |
  | 用户自己修改登录密码 | **不受影响** |
  | 管理员改角色 | 不受影响（每次请求从数据库取当前角色） |

  OPDS 密码不和 `token_version` 挂钩（否则用户改登录密码也会连带作废）。
- 每次请求以数据库为准校验：用户存在、已开通 OPDS。`must_change_password` 的账号拒绝（与现有中间件一致）。
- 允许纯 HTTP 访问（局域网墨水屏常只用 HTTP）；「阅读 App」页面在当前通过 HTTP 访问时提示「HTTP 下密码明文传输，建议在外网使用 HTTPS 地址」（我的决定）。
- 失败认证限流：复用 `express-rate-limit`，与 `credentialLimiter` 同等强度（只计失败）。
- 认证通过后 `req.user` 与现有一致（`userId`、`role`），以便「我的书架」等按用户取数据。

### 2. 目录结构（Navigation / Acquisition feeds）

根目录 `/opds`（navigation feed）：

| 条目 | 内容 |
|---|---|
| 最新入库 | 按 `imported_at` 倒序 |
| 最近在读 | 当前用户的 `reading_history`，按最近打开倒序 |
| 我的书架 | 当前用户的 `shelf` |
| 分类 | 多级分类逐级导航；每级先列「本分类全部书」（含下级），再列子分类；显示书数 |
| 作者 | 按作者名分组（拼音 / 首字母索引交给实现者，书多时可先按首字母分页） |
| 系列 | 系列列表 → 系列内的书（按系列内顺序） |
| 全部书籍 | 按书名排序 |

- 所有书目列表分页，每页 50 条，用 `rel="next"` / `rel="previous"` / `rel="first"` 链接。
- 搜索：提供 OpenSearch 描述文档（`rel="search"`，`type="application/opensearchdescription+xml"`），按书名、作者子串搜索，规则与书库页搜索一致。

### 3. 每本书的条目

- `title`（显示书名，与网页版同一套「显示书名」规则）、`author`、`summary`（纯文本）、分类（`category`）、`updated`、`dc:language` zh。
- 封面：`rel="http://opds-spec.org/image"` 与 `.../image/thumbnail` 指向现有 `/covers/...`。**系统生成的 SVG 默认封面不提供**（很多客户端不支持 SVG）——可由实现者改成提供 PNG 版本，若成本低。
- 下载链接（`rel="http://opds-spec.org/acquisition"`）：

| 书的格式 | 提供 |
|---|---|
| EPUB | EPUB（若读取需要修正，则给修正后的文件） |
| PDF | PDF 原文件 |
| TXT | **转换后的 EPUB（第一个链接）** + TXT 原文件（第二个链接，统一转 UTF-8 输出） |
| UMD | 转换后的 EPUB |

- 下载地址形如 `/opds/books/:id/download.epub` / `.pdf` / `.txt`；`Content-Disposition` 文件名用「书名 - 作者.扩展名」（中文用 RFC 5987 `filename*` 编码）。
- 下载**不**写阅读历史 / 进度（下载 ≠ 在读）。

### 4. TXT / UMD → EPUB 转换

- 来源：现有解析插件（`getReaderPlugin`）的 `getChapters()` + `getChapterContent()`；**章节标题与网页阅读器一致**，应用 `book_chapter_overrides`（`routes/reader.ts` 的 `getOverridesMap`，我的决定），覆盖标题的变化也要让缓存失效。TXT / UMD 的章节内容已是转义过的 `<p>` 段落 HTML，编码问题已由 TXT 解析器处理。
- 输出 EPUB 3（兼带 EPUB 2 的 `toc.ncx`，老阅读器 / KOReader 兼容更好）：
  - `mimetype` 第一项、不压缩；
  - 每章一个 XHTML，章节标题作 `<h2>`；
  - 目录含 `groupTitle`（如「第一部」）作为上一级；
  - 元数据：书名、作者、简介、语言 zh、标识符用书 id；有栅格封面时把封面放进 EPUB。
  - 简单的内嵌 CSS（段首缩进、行距），不带字体。
- 缓存：`DATA_DIR/opds-cache/`，文件名含 书 id + 源文件 mtime + 转换器版本号（转换逻辑改了就升版本，旧缓存自然失效）。书名 / 作者 / 封面改了也要失效（把这几项的哈希放进文件名，或其他等效办法，由实现者定）。生成新版本时删掉同一本书的旧缓存文件。书被删除时清掉缓存。
- 首次下载时同步生成，然后返回；同一本书并发请求只生成一次（参照 `pendingLoads` 的做法）；全局同时转换数量做限制（`p-limit`，如 2）。
- 超大书（如万章 TXT）也必须能转完；转换期间不能把整本内容一次性堆在内存里超出现有解析器本身的占用（流式写入或逐章加入 zip 均可，由实现者定）。
- 转换失败：返回 `500` 和可读原因，不写缓存。

### 5. 读取时修正过的 EPUB

- `parser-epub.ts` 的 `repairZipEndRecord()` 只在读取时修正、原文件不动。下载时若原文件无法正常打开且修正后可以，返回修正后的内容（可缓存到同一缓存目录）。
- `status = 'damaged'` 的书不出现在任何列表里，直接访问其下载地址返回 `404`。

### 6. 用户界面（网页）

- 设置页只有管理员能进；普通用户只有账户菜单里的「修改密码」。因此在**账户菜单新增「阅读 App（OPDS）」**一项，进入一个新页面（我的决定），内容：
  - 书目源地址（根据当前访问地址拼出 `https://域名:端口/opds`，带「复制」按钮；若设置了「站点公开地址」则用它）。
  - 用户名。
  - 未开通：「开通」按钮 → 生成 OPDS 密码并**只显示这一次**（带复制）。
  - 已开通：显示开通时间、「重置密码」「关闭」。
  - 简短说明：在 KOReader / KyBook / 静读天下里添加 OPDS 目录时填这三项；提示 TXT 会转成 EPUB 下载。
- 手机布局适配（与现有页面一致）。
- 后端接口：`/api/v1/opds/credentials`（GET 状态 / POST 开通或重置 / DELETE 关闭），走现有 JWT，写进 `docs/api.md`。开通 / 重置 / 关闭记审计日志。
- **管理员管控（用户决定）**：设置 → 用户管理列表加「OPDS」一列（已开通 / 未开通、开通时间），已开通的可点「关闭」（二次确认，记审计日志）。管理员**不能**替用户开通或查看密码。对应管理员接口（如 `DELETE /api/v1/settings/users/:id/opds`），写进 `docs/api.md`。

### 7. 数据

- 新表（或 `users` 加列，由实现者定）保存：user_id、OPDS 密码哈希、创建时间、最后使用时间（可选）。
- 用户被删除时一并删除。

## 留给实现者决定

- 作者导航的分组和排序方式（首字母、拼音库是否引入）。
- 缓存失效键的具体做法（只要满足第 4 节的失效条件）。
- SVG 默认封面是否转 PNG 提供。
- feed 的 XML 生成方式（模板字符串 + 转义即可，不强求库）。
- 测试用哪些真实客户端验证；至少要用一个真实 OPDS 客户端（如 KOReader 桌面版或 Readest）走通「添加源 → 浏览 → 搜索 → 下载 TXT 转换的 EPUB 并打开」。

## 验收

1. 用 OPDS 客户端添加源，Basic 认证通过；错误密码 401；重置后旧密码失效；关闭后 401；管理员重置该用户登录密码后 401；用户自己改登录密码后仍可用；管理员在用户管理里关闭后 401。
2. 根目录各入口可浏览，分页、搜索可用；「最近在读」「我的书架」只显示自己的。
3. EPUB / PDF 下载可打开；TXT（含 GBK）、UMD 下载的 EPUB 有目录、无乱码，在客户端能按章跳转。
4. 读取时修正过的 EPUB 下载后能打开；损坏 / 重复 / 乱码书不出现，直接访问 404。
5. 改书名后重新下载，EPUB 里的书名是新的。
6. 万章级 TXT 能转换成功，期间服务正常响应其他请求。
