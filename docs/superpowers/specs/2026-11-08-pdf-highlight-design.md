# PDF 支持划线与批注（设计）

> 学习版（`study` 分支）。划线 / 批注功能本身只在学习版存在（main 没有 `highlights`），因此本功能只在 `study` 开发。

## 为什么做

用户读的 PDF 很多（文字版、扫描版、图片版都有）。现在普通格式（TXT / EPUB 等）可以划线、写批注，划线进入划线列表、学习导图与「笔记整理」，由 AI 整理成文；但 PDF 两种打开方式都不能划线，PDF 里读到的要点进不了笔记体系。

用户的目标（原话）：「希望画下来拷贝到文档」——确认为：**PDF 里划下的内容和普通书的划线一样进入划线列表与笔记整理**，而不是复制到外部 Word。

## 目标

1. 文字版 PDF：在阅读器中选中文字 → 划线、写批注，交互与普通书一致（选中后弹出同样的划线 / 批注工具条，已划部分在页面上显示底色，点已有划线可改批注、删除）。
2. PDF 划线与普通划线是同一种数据：出现在阅读器「笔记」列表、划线管理、学习导图（可 AI 展开）、笔记整理（AI 生成 / 更新），笔记整理里的书本图标可以跳回 PDF 对应页并定位到划线。
3. **扫描版 / 图片版不做（用户决定）**：检测到当前页没有可选中的文字时，划线按钮灰化，鼠标移上去提示「PDF 格式不支持」。
4. 对外 API：沿用现有划线接口，不新增破坏性字段；如需新增字段只加不改，并写进 `docs/api.md`。

## 不做 / 反目标

- 不做 OCR、不做框选区域（扫描 / 图片页的划线留给以后）。
- 不修改 PDF 原文件，不把划线写进 PDF（不做 PDF 注释导出）。
- 浏览器原生打开（iframe）方式不支持划线。
- 反目标：划线位置错乱——划在第 3 页某句，刷新后底色落到别处或别的页；划线后文字选不中 / 页面画面与可选文字错位，影响正常阅读。
- 反目标：为 PDF 另造一套笔记数据，导致导图 / 笔记整理看不到 PDF 划线。

## 范围与判断规则

- **只在「按页渲染」方式（PDF 插件开启，`pdfUsePlugin = true`）中支持**。管理员把 PDF 改为浏览器原生打开时，划线入口灰化，提示「当前 PDF 打开方式不支持划线，可在设置中开启 PDF 插件」。（我的决定，用户认可）
- **按页判断**：某一页的文字层没有可选中的文字（空白或只有空格）→ 该页视为扫描 / 图片页，划线按钮灰化并提示「PDF 格式不支持」。文字页与扫描页混排的 PDF，文字页照常可划。（我的决定，用户认可）
- 「划线按钮」指阅读器里与划线相关的入口：选中文字后的划线 / 批注工具条（扫描页上选不中文字，自然不会弹出），以及顶栏 / 侧栏的「笔记」入口——笔记入口在 PDF 中保持可用（能看到其他页的划线），灰化只针对当前页无法新建划线的情况。具体哪些入口灰化、灰化文案放在哪里（例如在扫描页上长按 / 拖选时给出一次提示）留给实现，但提示文字必须是「PDF 格式不支持」。

## 怎么做（已定部分）

- **文字层**：`PdfPage.vue` 在 canvas 之上叠一层 pdf.js（前端已有依赖 `pdfjs-dist` 6.4.299）的文字层（TextLayer），文字透明、可选中、与画面对齐；随页面宽度变化重排。画面渲染逻辑不变。
- **锚点**：PDF 每页即一「章」（现有约定：`chapterIndex = 页码 - 1`）。划线锚点沿用现有方式——`chapterIndex` + 文字层 `textContent` 中的 `[startOffset, endOffset)` + 原文 `text`；恢复时沿用 `locateHighlight`（偏移对不上时按原文就近查找）。
- **显示**：划线底色画在文字层上（沿用 `mark.hl` 的思路，文字层文字透明，底色半透明可见），有批注的划线样式与普通书一致。
- **后端**：划线接口不变。后端 PDF 每页文字由 `pdf-parse`（较旧版本 pdf.js）抽取，与前端文字层的文字在空白 / 换行上可能不一致——凡是后端用划线原文在页文字里定位的地方（如 AI 展开取上下文、笔记整理跳转原文），要能容忍空白差异（找不到时退化为整页上下文，不报错）。

## 审查后补充的决定（我的决定）

- **划线原文要可读**：pdf.js 文字层行尾用 `<br>`，`textContent` 不含换行，跨行划线会出现英文单词粘连；后端抽取时会去掉「伪粗体」重复绘制的字，前端文字层不会，可能出现「重要重要」。实现时在文字层里补上换行 / 空格文本节点、按后端相同规则去重，使存下的 `text` 可读，且锚点仍与文字层 `textContent` 一一对应。不新增 API 字段。
- **后端定位失败时用整页**：划线原文在后端页文字里找不到时（空白差异等），AI 展开取整页作为上下文，并且 PDF 场景下整页视为已读，不按阅读进度段落号截断（PDF 的进度段落号基本为 0）。
- **跨页选区**：瀑布流里选区跨两页时，按现有「跨章」规则拒绝（与普通书一致）。手机触屏选字沿用浏览器原生选择。
- 管理员把 PDF 改回浏览器原生打开后，从笔记整理跳回已有 PDF 划线：沿用现有处理（去掉跳转参数直接打开）。

## 留给实现

- 文字层的具体接入（`TextLayer` API 用法、样式、与现有 `pdf-chapter` 容器和 `highlight-anchor` 工具函数的衔接）。
- 章节模式与瀑布流（滚动）模式都要支持；瀑布流里多页同时存在，按页分别应用划线。
- 「本页无文字」的判定细节（例如文字层字符数为 0 或去空白后为 0）与灰化 / 提示的具体呈现。
- 从笔记整理 / 划线列表跳转到 PDF 划线时的定位与闪烁提示。
- 测试范围：锚点计算与恢复（含空白差异）、无文字页判定、后端容错的单测；浏览器实测文字版、扫描版、混排 PDF 各一本。
